# 方案 A′「写入系统信任库」风险说明

> 生成时间：2026-10-15 12:55
> 针对动作：`certutil -addstore -f -user Root certs\ghmirror-ca.crt`
> 证书：`RRL Local Mirror CA`，SHA1 指纹 `E348D7F96684F6C8A9F8F42E0DA2519C96748B34`
> 结论先行：**写入本身只加一张证书、可一键删除、不碰系统其它部位；真正的风险是「这张证书的信任范围远大于本次需求，且私钥以明文躺在磁盘上」**

---

## 一、「写入」到底写了什么（先把范围钉死）

| 项目 | 事实 |
|---|---|
| 动作 | 把 1 张自签根证书加入**当前用户**的「受信任的根证书颁发机构」 |
| 实际落点 | 注册表 `HKCU\Software\Microsoft\SystemCertificates\Root\Certificates\E348D7F9...8B34` |
| 数量 | **1 张**证书（不是一批、不是全库覆盖） |
| 需要管理员？ | **否**。CurrentUser 库普通用户即可写入/删除，不触发 UAC |
| 是否改 hosts？ | 否 |
| 是否改 MAA / MaaEnd 配置？ | 否（`gui.json`、`mxu-MaaEnd.json` 全程未动） |
| 是否装系统级(LocalMachine)证书？ | 否 |
| 是否装服务/驱动/开机自启？ | 否 |
| 如何卸载 | `certutil -delstore -user Root <指纹>`，或双击 `restore.bat`（幂等，重复运行无害） |

## 二、真正的风险（按严重度排序）

| # | 风险 | 说明 | 严重度 |
|---|---|---|---|
| **R1** | 信任范围是「整个 Windows 账号」，不是「只对 MAA」 | 一旦装进 Root 库，**凡是读取 Windows 证书库的本账号应用**（Chrome/Edge、.NET 程序、schannel 版 curl、PowerShell、其他 Rust/schannel 程序……）都会信任这张 CA。我的代理只对 `github.com` 使用它，但「信任」这个事实本身是**账号级**的。 | 高 |
| **R2** | 私钥在磁盘上、且**未加密** | `certs\ghmirror-ca.key` 是 openssl 用 `-nodes` 生成的**明文私钥**。任何人/任何程序拿到这个文件，就能为**任意域名**签发被本账号信任的证书，做**静默** MITM（浏览器不报警）。 | 高（条件触发） |
| **R3** | 有效期长达 10 年，清理可能遗漏 | CA 有效期 3650 天。若代理被强杀、你直接关掉它的窗口、或收尾脚本没跑完，证书会留存。下次 `start`/`stop`/`restore.bat` 会自愈，但取决于你之后还会不会再跑。 | 中 |
| **R4** | 杀软 / EDR / 企业策略可能告警或回滚 | 「把自签 CA 装进 Root 库」正是恶意软件的常用手法。Windows 会弹**安全警告确认框**，安全软件可能标记，域管环境可能被组策略回滚或触发合规告警。 | 中 |
| **R5** | 运行期 `github.com` 流量在本地被解密 | 代理只监听 `127.0.0.1`，且**仅解密 github.com**；但内容经第三方 `ghfast.top` 中转。完整性靠 SHA256 比对（已成功验证过 1 次，但**不是自动校验**）。 | 低-中 |
| **R6** | 本地代理无鉴权 | 代理运行期间，本机任何进程都能连 `127.0.0.1:8899` 借道出网。 | 低 |

## 三、代码里**已经规避掉**的（这些担心是多余的）

- **认证凭据不出本机**：代理只转发 `range / if-range / if-none-match / if-modified-since / user-agent / accept` 六个头，**`Authorization`、`Cookie` 等一律不透传**给镜像站。已核对源码 `ghproxy.py` 第 87–88、213–216 行。
- **只拦一个域名**：默认白名单仅 `github.com`，**其余任何域名纯 TCP 透传**，不解密、不改写、不看内容。
- **拦截是「进程级」的**：MAA / MaaEnd 通过 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量接入，只对**由脚本启动的那个进程**生效。你不通过脚本启动的程序**根本不走代理**（这是「便宜」的前提）。
- **免管理员**：CurrentUser 库，不触发 UAC。
- **三层收尾**：① 脚本正常退出时清理；② 代理被 Ctrl+C / 异常退出时凭标记文件自动 `delstore`；③ 被强杀漏了，用 `restore.bat` 幂等还原。
- **不写任何程序配置**：没有改配置文件、没有开机自启、没有常驻服务。

## 四、最坏情况推演（诚实版）

```
你装了 CA
  → 清理漏了 / 忘了（R3）
  → 期间 certs\ghmirror-ca.key 被某个能读文件的东西获取（R2）
  → 攻击者可对你这个 Windows 账号做「任意域名」的静默 HTTPS 中间人
```

前提是「本机已被入侵」或「该目录被同步到网盘/备份」。但在这之前，这张 CA 把攻击的**难度和可见度都显著拉低**了 —— 这是它和高危漏洞同类的原因。

## 五、把风险再压低的加固项（建议：先做 H1 + H2 + H3，再装）

| 编号 | 做法 | 收益 |
|---|---|---|
| **H1** | 代理**下完更新包就立刻自删 CA**，而不是等整个程序关闭 | 暴露窗口从「整场会话（可能几十分钟）」压缩到「几十秒」 |
| **H2** | 重新签发证书：CA 有效期 30 天、叶证书 7 天 | 万一漏删，损害窗口从 10 年降到 1 个月 |
| **H3** | 给 `certs` 目录设 NTFS 权限「仅本人可读」；确认 `D:\RRL` **不在** OneDrive / 网盘同步范围 | 堵住 R2 的入口 |
| **H4** | 收尾时显式校验 Root 库确实没有 RRL 记录 | 消除「以为删了其实没删」 |
| **H5** | 专门开一个 Windows 账号跑 MAA | 信任隔离，但该账号内仍是账号级 |

## 六、若不想承担任何 CA 风险（替代路线）

- **方案 B：一键更新脚本** —— 脚本经 `ghfast.top` 下载 + SHA256 校验 + 解压覆盖，**完全不碰信任库**。代价：没有程序内自动更新，需手动双击。
- **方案 C：MirrorChyan** —— 用程序原生国内 CDN，**不碰信任库**，最稳。代价：需要你提供 CDK。

---

## 七、一句话结论

写入**不会写坏系统**（就一个注册表项、可一键删、不碰 hosts 与程序配置）；它的风险本质是**权限让渡** —— 在证书存在的期间，你这个 Windows 账号的 HTTPS 信任链上多了一个由本地私钥掌控的根。**可控，但必须知情。**
