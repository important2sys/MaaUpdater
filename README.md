# MaaUpdaterBat

面向 Windows 的 **MAA / MaaEnd 更新加速工具集**，覆盖三条相互独立的更新链路：

| 链路 | 对象 | 说明 |
|---|---|---|
| ① | **MAA 程序本体** | 全量包或增量包（OTA） |
| ② | **MAA 资源** | 关卡坐标、模板图、`stages.json` 等 |
| ③ | **MaaEnd 程序本体** | 全量包 |

工具**绕开程序自带的更新器**，自行完成「查版本 → 下载 → 校验 → 备份 → 覆盖 → 复核」。
整个过程不安装证书、不修改 hosts、不写入程序自身配置。

> **第三方非官方工具。** 本项目与 MAA / MaaEnd 开发组、Mirror 酱、鹰角网络均无隶属
> 关系，亦未获其授权或背书。**默认直连 GitHub，不经过任何第三方服务器**；如需启用
> 镜像加速，请先阅读 [`安全提醒与免责声明.md`](安全提醒与免责声明.md)（含法律风险提示）。

---

## 一、项目背景

本工具的存在前提是**本机到 GitHub 的文件分发通道不可用** —— HTTPS 直连被限速且长
连接会被中途重置，MAA 官方元数据中的镜像数组又已全部为空、三个官方 CDN 域名均已
失效。两者叠加，使 MAA / MaaEnd 自带的「检查更新」在此网络下几乎必然失败。

为此本工具绕开程序自带的更新器，自行完成上述全流程。

---

## 二、功能范围

- **三条链路的完整更新流程**：版本探测、包选择（优先增量）、镜像与直连候选、SHA256
  或语义校验、备份、解压覆盖、`removelist` 应用、版本复核。
- **图形界面与命令行双入口**，共用同一份配置与同一套更新逻辑。
- **安装目录手动指定**，解析契约是「要么使用指定目录，要么明确报错」，绝不静默回退。
- **资源更新按 CRC32 逐文件比对**，仅写入内容变化的文件。

不在范围内：不修改游戏、不注入进程、不读取账号信息、不收集也不上传任何数据
（本工具没有遥测，没有联网上报）。

## 三、安全与免责

**这是第三方非官方工具，按「现状」提供，不附带任何担保。**

关于镜像源的性质、各链路校验能力的差异、程序会做与不会做的事项、相关的**法律风险
提示**（官方软件许可、名称与商标、游戏服务条款、第三方服务、本项目的授权），以及
完整免责条款与参考镜像地址清单，均集中在：

> **[`安全提醒与免责声明.md`](安全提醒与免责声明.md)**

需特别指出：不同更新链路的校验能力**并不相同**。程序本体有 GitHub 官方 SHA256
摘要兜底，摘要不符会拒绝写入；而 **MAA 资源包没有官方摘要**，仅能做语义校验与
CRC32，无法抵御精心构造的替换。因此走镜像更新资源时，安全性完全取决于使用者是否
信任该镜像站。这也是为什么镜像在本项目中**默认关闭**。

## 四、系统构成

```
MaaUpdaterBat\
├── MaaUpdater.bat          唯一入口，双击即打开图形界面
├── 使用说明.txt            面向最终用户的简要说明
├── 安全提醒与免责声明.md    安全提醒、法律风险与免责条款
└── ghupdate\              工具主体（命令行 + 图形界面，零第三方依赖）
```

`ghupdate\` 是唯一的功能模块，其详细说明见
[`ghupdate/README.md`](ghupdate/README.md)。

## 五、环境要求

- **Windows**（硬约束：版本探测依赖 PE 文件版本资源与 `tasklist`）
- **Python 3.8+**
  - 命令行入口会自动探测：托管 venv → 托管 3.13.x → 系统 Python 3.12/3.13/3.14 →
    `where python`
  - **图形界面另需一个带 tkinter 的解释器**。tkinter 随解释器编译，无法通过 `pip`
    补装；`ghupdate-gui.bat` 会逐个探测并选出可用者，全部不可用时会列出探测过的
    路径与修复方法，且不影响命令行使用
- **无需任何第三方 pip 包**（全部使用 Python 标准库）

## 六、快速开始

### 图形界面（日常使用）

双击项目根目录下的 **`MaaUpdater.bat`**。该脚本转发至
`ghupdate\ghupdate-gui.bat`，后者会自动挑选一个可用的解释器，随即以 `pythonw` 把
界面交给系统 —— 启动器自身的控制台随即关闭，不会留下多余的窗口。

界面等价入口位于 `ghupdate\`：

```
ghupdate-gui.bat            # 无控制台窗口
ghupdate-gui-debug.bat      # 保留控制台以便查看报错
```

### 命令行

```
cd ghupdate
update-all.bat              # 中文菜单
update-all.bat check        # 三条链路全部干跑，不下载任何文件
update-all.bat maa          # 仅更新 MAA 程序本体
update-all.bat maares       # 仅更新 MAA 资源
update-all.bat maaend       # 仅更新 MaaEnd
update-all.bat all          # 本体 -> 资源 -> MaaEnd 依次更新
```

两个入口**共用同一份 `config.json` 与同一套更新逻辑**，在界面中修改的设置对命令行
立即生效。

> **更新前必须先完全退出对应程序。** 运行中的程序会占用待替换文件，工具检测到目标
> 程序正在运行时会直接拒绝执行。

## 七、安装目录与配置

安装目录为**手动指定**，镜像、代理、超时、备份等开关均位于 `ghupdate\config.json`，
界面中的「设置…」可修改全部选项。

安装目录的解析优先级为 `--install` > 环境变量 > `config.json` > 交互询问，详见
[`ghupdate/README.md`](ghupdate/README.md)。

常用命令：

```
update-all.bat maa --show-config                          查看当前生效配置及各项来源
update-all.bat maa --install "D:\RL\MAA-v6.19.0-win-x64"  指定安装目录（校验通过后记住）
update-all.bat maa --inspect "D:\RL"                      检查目录并列出子目录候选
```

## 八、已验证结果

### 程序本体更新（2026-10-15）

| 程序 | 更新前 | 更新后 | 包体量 | 耗时 |
|---|---|---|---|---|
| MAA | v6.18.0 | **v6.19.0** | 19.57 MB（OTA 增量） | 60.8 s |
| MaaEnd | v2.30.1 | **v2.32.0** | 295.21 MB（全量） | 227.1 s |

两个包的 SHA256 均与 GitHub 官方 `digest` **逐字符一致**；用户配置（`config/gui.json`、
`config/mxu-MaaEnd.json`）时间戳未变，登录状态与设置完好。

### 资源更新（2026-10-15）

| 项目 | 结果 |
|---|---|
| 资源包 | 13.53 MB，下载耗时 18.0–34.8 s（395–780 KB/s） |
| 包结构 | `MaaResource-main/resource/**` 共 5,311 个文件 |
| 版本比对 | mirrorchyan `version_name` 与包内 `resource/version.json` 的 `last_updated` 完全一致 |
| 全量比对 | 本机 5,311 个文件逐个 `size` + CRC32 比对 → **5311 相同 / 0 需写入**，零误判 |
| 修复演练 | 篡改 `stages.json` 并删除一个包内文件 → 仅写入 2 个文件（788 KB），其余 5,309 个文件未变 |
| 用户数据 | `config.json` / `ocr_config.json` / `copilot` / `custom_infrast` 全程未被触碰 |

## 九、已知限制

- **镜像默认关闭**，因此开箱即用的是直连通道：较慢，且可能中途断线。如需提速，须
  手动启用镜像（界面「设置…」或 `config.json`），并自行评估该镜像站的可信度。
- 镜像**无法代理 `api.github.com`**（实测返回 403），因此「查版本 / 取官方摘要」始终
  走直连，仅「下载文件」经镜像。
- **MAA 资源包不支持断点续传**：镜像与直连对 Range 请求均返回 200 全量，中断后需
  重新下载完整的 13.5 MB。
- **资源版本的唯一来源是 mirrorchyan**。该服务不可用时无法获取远端版本号，也就无法
  校验资源包，此时工具**直接报错退出**，而非跳过检查强行下载。
- 无法复刻 `MAA.Updater.exe` 的私有 update plan 协议（未公开），因此不具备「父进程
  退出后自动替换」的能力，要求先手动关闭程序。
- **目录名不代表版本**（例如 `MAA-v6.9.5-win-x64` 中实际运行的是 v6.19.0）。判断
  「是否已是最新」一律以程序内部版本为准，`--inspect` 亦显示真实版本。
- 磁盘占用：MAA 增量包约需 100 MB；MAA 全量包约需 600 MB；MaaEnd 全量包约需 900 MB
  （含下载、解压与备份）。
- **资源更新比程序本体更新频繁得多**，日常真正需要执行的多为 `maares`。

## 十、回滚

每次更新前会自动备份至 `ghupdate\_backup\<程序>-<时间戳>\`，将其中内容复制回安装
目录即可还原：

```
xcopy /E /Y /I "D:\RRL\MaaUpdaterBat\ghupdate\_backup\MAA-<时间戳>\*" "D:\RL\MAA-v6.19.0-win-x64\"
```
